What Leaves With Them

When a colleague leaves, a team lead has to find out who owns what now, and why, from chat, tickets and documents that disagree and keep changing.

67%

of 1,000 IT managers at large UK and US organizations are concerned about losing knowledge when people leave

64%

say their organization has already lost knowledge that way

Who it is for

A team lead or new owner who asks "Who owns billing-api now?" or "Who decided ADR-0014?" and needs an answer they can check, not a confident guess from an old copy.

Source: Sinequa press release, August 2022 (survey of 1,000 IT managers, UK and US)Synthetic company: Quillfield Billing

The solution2/8

Two agents that check each other against the source

  • Investigator answers from a memory graph and cites every claim: record id, one quoted line, the claim it backs.
  • Verifier re-reads each cited record through Zetaris, in the system it lives in. A quote that is not there any more is rejected, even if a model says it fits.
  • A rejection goes back with notes and the record as it reads now. The Investigator revises, at most twice.
  • Only an answer whose every citation survived is stored. Everything else says what was dropped and why.

Output: answer · citations (system, id, quote, verdict) · dropped citations with the reason · rounds · stored or not · trace file

Sponsor technology5/8

Zetaris for every read, Nightshift for every model call

Zetaris

  • 3 SELECTs build the memory graph: 403 records, 0 field differences from the corpus
  • The Verifier re-reads each cited record by id; p50 0.11 s (chat), 0.18 s (docs)
  • Absence: one UNION ALL over the three systems
  • Spike: JOIN 45/45, tampered quotes 8/8 rejected

Meterless Nightshift

  • Primary provider for both agents, one app id per agent with a one-lane allowlist
  • Every response checked: routed model, lane, cost 0; a mismatch raises, it is not hidden
  • Receipts signed Ed25519 by the daemon, exported to logs/receipts-*.jsonl

Meterless H-MEM + NVIDIA

  • H-MEM stores answers that passed the gate, recalls them before the model answers, takes the Verifier's verdict as feedback (0.70 → 0.75 in the cross-session proof)
  • Nemotron 3.5 Lightning: Investigator (tool calls). Nemotron 3 Nano: Verifier (JSON verdicts)

What was unique6/8

The Verifier trusts the source, not the memory and not a model

Before any answer counts, the Verifier goes back through Zetaris to the system that owns each cited record and re-reads the line. That check is plain code, and no model can overrule it.

In one untouched run, the Investigator's model quoted a chat sentence as if it were ADR-0009, and the Verifier's model said "supports". The quote check rejected it, and the revision quoted the ADR's own line.

Only answers that survived reach H-MEM, so the agents' memory does not learn from a stale or misquoted answer.

Future enhancements8/8

Next: real systems, same rule

  • Refresh the memory graph when the Verifier finds a record changed at its source (today the catch is reported, the graph keeps the old copy).
  • Zetaris semantic layer with a read-only agent user, so the agents see only the views they need.
  • Case-insensitive absence checks and semantic recall in H-MEM (both lexical today).
  • A stronger Verifier model where Nemotron 3 Nano judged a reported conflict as a contradiction.
  • More sources behind Zetaris: meeting notes, HR system end dates, code ownership files.
  • A pilot on a real team's records, measured against the same benchmark questions.
  • Handoff cards that a successor confirms, written back through the same gate.
